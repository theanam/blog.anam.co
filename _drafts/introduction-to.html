I am really happy with docker. It's easy, fast and convenient. most importantly: it gets my work done. One of my colleagues mentioned rkt once when I was learning docker. I did not pay enough attention that time. I recently revisited rkt, and it has some cool features worth exploring.

The main problem of technology is, whenever one problem has two different solutions, If you know one. It gets really tough to learn an alternative solution without unlearning the first. When I first started exploring rkt, I had to face a lot of trouble. The main reason was: I was thiking with my docker mindset. Things got easier eventually.

The very first problem for me was the Mac compatibility. Docker does not directly run in Mac, It runs on HyperKit. But the folks at Docker made it really easy to run docker in mac. It's as simple as downloading and installing an application. On the other hand: rkt is more DIY and has to be run inside a Vagrant box (at the time of writing this blog) . I had to install Vagrant, Virtualbox. And then run rkt inside a box: 

git clone https://github.com/rkt/rkt
cd rkt
vagrant up

the process is more or less the same for Windows. But if you are using Linux. You have to refer to the installation guide that's much simpler btw.

Let's discuss my experiences with rkt,

Nothing like Dockerfiles?

The very first thing that felt like obvious bummer is the lack of something similar as Dockerfile the magic configuration file is almost like a source code for Docker images. In rkt, there's no such thing. And what sounds like added insult to injury: rkt doesn't seem to have it's own feature of creating images. Instead it relies on App Container Images , and an additional tool called acbuild is used. Both of the tools are made by CoreOS though.

acbuild:

At that point I started to doubt my decision of exploring rkt, but still continued. Then the good things started to appear. The tool acbuild for example: is a wonderful tool. And with our old friend, Unix shell scripting, Something very similar to dockerfile can be achieved.  

App Container Images:

The tool creates .aci (App Container Images) file. That can be run with rkt. With that being said, Docker images can also be run with rkt. Cool! isn't it?

acbuild felt more like git to me. You start creating image with the command acbuild start that starts you up with a blank image. Then you run acbuild commands to gradually build the image. Below are the steps to make a  simple image to run a go application.

# Start with a blank 
acbuild begin

# Set the image Name
acbuild set-name theanam/hello

# Copy files to image
acbuild copy hello /bin/hello

# Set the executable.
acbuild set-exec /bin/hello

# Open port 5000
acbuild port add www tcp 5000

# Add Labels
acbuild label add version 0.0.1
acbuild label add arch amd64
acbuild label add os linux

# Add Annotation
acbuild annotation add authors "Carly Container <carly@example.com>"

# Write Image in a file
acbuild write hello-0.0.1-linux-amd64.aci

# End build
acbuild end
